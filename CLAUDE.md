## What This Is

A real-time management dashboard for 13 outpatient clinic units ("ambulatórios") across São Paulo and other Brazilian cities. It tracks physician presence, room occupancy, and consultation metrics. The entire UI is in Brazilian Portuguese.

**There is no database.** All state is generated on-the-fly by a deterministic simulation engine (`src/lib/simulacao.ts`) keyed to the current timestamp. Every page polls `/api/estado-atual` every 30 seconds.

## Architecture

### Data flow
```
src/data/dados-mestres.ts  (static master data)
        ↓
src/lib/simulacao.ts       (deterministic simulation, LCG seed)
        ↓
src/app/api/*/route.ts     (Next.js API routes, force-dynamic)
        ↓
src/app/**/page.tsx        (client components, fetch + useState + 30s polling)
```

### Master data (`src/data/dados-mestres.ts`)
- `UNIDADES` — 13 clinic units (u01–u13) with real addresses, coordinators, specialties, and brand colors
- `MEDICOS` — 179 physicians (m01–m179) assigned to units and shifts (`manha`/`tarde`/`integral`)
- `TODAS_SALAS` — Room definitions. u01, u02, u04, u07 have real floor-by-floor layouts; the remaining 9 units get rooms auto-generated by `gerarSalas()` based on their specialty list

### Simulation engine (`src/lib/simulacao.ts`)
Uses a Linear Congruential Generator (`seed(n)`) — **not** `Math.random()` — so state is reproducible for a given point in time. Key behaviors:
- ~5% of physicians are marked absent each day (seeded by date + position index)
- Consultation slots are 20-minute cycles; status cycles within each slot (0–14 min = `em_atendimento`, 15–17 min = `pausa`/`aguardando`, 18+ = `aguardando`)
- Weekends produce no active physicians

Exported functions: `gerarAlocacoes`, `gerarEstadoSalas`, `gerarResumoUnidades`, `gerarKPIs`, `gerarDadosHistoricos`, `gerarProdutividadePorEspecialidade`

### API routes
| Route | Returns |
|---|---|
| `GET /api/estado-atual` | `{ kpis, alocacoes, estadoSalas, resumoUnidades, timestamp }` |
| `GET /api/produtividade` | `{ historico, porEspecialidade, timestamp }` |

Both routes set `export const dynamic = 'force-dynamic'`.

### Pages (all in `src/app/`)
| Route | Purpose |
|---|---|
| `/` | KPI cards + unit status table + alerts panel |
| `/locacao` | Filterable real-time physician allocation table |
| `/mapa` | Unit picker grid |
| `/mapa/[unidadeId]` | Room grid grouped by floor with hover tooltip |
| `/produtividade` | Recharts line/bar charts for historical + by-specialty data |
| `/medicos` | Physician directory |
| `/unidades` | Unit info cards |

### Components (`src/components/`)
- `Sidebar` — fixed left nav (dark slate), 6 nav items, width defined by `--sidebar-w: 256px` in CSS
- `KPICard` — metric card with icon, trend arrow, subtitle
- `RelogioAtualizacao` — live clock + countdown that fires `onAtualizar` callback every N seconds
- `StatusBadge` — `BadgeMedico` and `BadgeSala` badge components

## Key Conventions

### IDs
- Units: `u01`–`u13`
- Doctors: `m01`–`m179`
- Rooms: `{unidadeId}-s{zero-padded-seq}` (e.g. `u01-s47`)

### TypeScript types (`src/types/index.ts`)
All domain types live here. Most important: `StatusMedico` (`em_atendimento | disponivel | pausa | ausente | aguardando`) and `StatusSala` (`ocupada | livre | manutencao | reservada`). The status→color/label lookup maps are in `src/lib/utils.ts`.

### Styling
- Tailwind with `@apply`-based utility classes defined in `globals.css`: `.card`, `.card-hover`, `.tabela-zebra`
- Status colors are centralized in `STATUS_MEDICO_COR`, `STATUS_MEDICO_DOT`, `STATUS_SALA_COR` in `src/lib/utils.ts` — use these maps instead of inlining colors
- Unit brand colors come from `unidade.cor` (hex strings), applied via inline `style={{ background: unidade.cor }}`

### Path alias
`@/` maps to `src/` (standard Next.js convention, confirmed in `tsconfig.json`).

### Adding a new unit
1. Add entry to `UNIDADES` in `dados-mestres.ts` (new id u14+, pick a `cor`, list `especialidades`)
2. Optionally add real rooms as `SALAS_U{id}[]`; otherwise `gerarSalas()` auto-generates them
3. Add physicians referencing the new unit id to `MEDICOS`
4. No API or routing changes needed — everything iterates over `UNIDADES`
